# Lifecycle audit

## Prioritized defects in prior implementation

1. **Critical — orphan race:** `scripts/desktop.py` starts a child before recording its identity. Manager death in that gap can leave an untracked server or PRoot. Initial state writes can also be interrupted.
2. **High — incomplete stop:** signaling only the PRoot and X11 roots does not prove guest descendants exited. `proot-distro kill PID` walks descendants with numeric PIDs, subject to reparenting and PID-reuse races. Never use container-wide kill.
3. **High — readiness attribution:** probing a display and finding an XFCE process does not establish that the responding server and window manager belong to the managed session. Display availability checks alone are racy.
4. **High — transitional process identity:** the launcher can record a `proot-distro` process before it becomes PRoot; old validation accepts only final PRoot arguments. Interrupted startup may prevent safe cleanup.
5. **High — no safe reconciliation:** Start is intentionally disabled; status of an existing state and Stop cannot recover it. Previous-boot status renames files, so status is not read-only.
6. **High — launcher not one-tap:** icon checks status but does not start stopped desktop or resume running desktop; callback completion can be missed while paused or after process recreation.
7. **Medium — regression gaps:** six prior WSL tests mostly check disabled paths, not a real running lifecycle, partial failures or ownership.
8. **High — false STOPPED and invalid boot metadata:** review found the current partial status/stop code can label missing state STOPPED without proving no untracked survivors. Missing `boot_id` may be treated as previous boot, rename state and yield STOPPED. Fix must fail closed.

## Review of isolated gated-launch experiment

The helper is not connected to Start. Review identified lost records on sequential launches, inherited standard streams/process group, unreported exec failure, incomplete initial state publication and FIFO state blocking. Source changes and focused WSL checks address these cases. Subsequent review found FIFO lock blocking, acceptance of missing persisted state during sequential launch, and a descriptor-test timing race; source fixes passed focused WSL tests and scoped re-review. Error-pipe EOF alone cannot prove exec succeeded, a timeout leaves ownership unknown, and stopped children can block pre-release reaping; no pidfd integration or complete lifecycle is present. Security re-review also found ambiguous socket errors treated as display vacancy and X11 process identity not bound to the recorded token. Socket preflight now fails closed on ambiguous errors including `ECONNREFUSED`, which can indicate a bound, non-listening abstract socket. A real bound-socket regression passes on WSL. This conservative check can reject vacant displays and remains racy; it is not an endpoint reservation. Legacy `start()` still invokes unsafe `launch()`; neither is reachable through `main` while Start is disabled. The exported Android launcher activity could be invoked by another app to cause automatic Start using the launcher's Termux permission. Automatic Start has been removed; source review confirms Start requires a button press. An external launch can still request status, foreground an already-running viewer and clear the local start marker. Intent action/category are not caller authentication. One possible design for one-tap Start is an explicitly installed home-screen widget with an immutable PendingIntent targeting a non-exported component, but this changes setup and does not make the app-drawer icon secure; it is not implemented or verified.

## Containment feasibility on tablet

Read-only inspection as Termux UID 10528 showed cgroup v2 mounted at `/sys/fs/cgroup`. `/sys/fs/cgroup/apps/uid_10528` and its `cgroup.kill` are owned by `system:system`; `/sys/fs/cgroup`, `/sys/fs/cgroup/apps`, that UID directory, `/dev/cpuctl`, `/dev/cpuset`, and `/dev/memcg` were not writable in the `run-as com.termux` check. No cgroup was created or modified. This shell retained `runas_app` SELinux context and inherited its caller's cgroup; the actual Termux app PID 2226 had `untrusted_app_27` context and membership `/apps/uid_10528/pid_2226`. The UID and process cgroup directories are `system:system` mode 775, so neither is writable by UID 10528 under discretionary access control; `run-as` also received `Permission denied` when inspecting the process cgroup's `cgroup.procs` and `cgroup.kill`. This does not establish all possible delegation mechanisms. `cgroup.kill` for the whole UID would also affect unrelated Termux services and must not be used.

Temporary `run-as com.termux` probes: `unshare --user` returned `Invalid argument`, `unshare --pid` returned `Operation not permitted`, and `unshare --user --map-root-user --pid --fork` returned `Invalid argument`. These probes do not establish whether every alternative namespace mechanism is unavailable. Without a verified delegated, session-specific containment boundary, PRoot ancestry, process groups, and pidfds cannot prove all desktop descendants have exited after supervisor death. Termux Python exposes `SO_PEERCRED` and `SCM_CREDENTIALS`; `SO_PEERCRED` on a private same-process socket pair returned that process's PID and UID 10528. This does not identify the peer of an actual Termux:X11 connection. The X11 connection still needs attribution to the owned server. A session-specific delegation and actual Termux:X11 topology would need separate verification; neither is established by the present checks.

## Deployment gate

Do not deploy or start the manager until crash/ownership, idempotence, display conflict and foreign-process tests pass and security review is complete. Unknown ownership must fail closed and preserve evidence. Do not claim graphical or one-tap success without observing the tablet display.
